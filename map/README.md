# aeolian map

The desktop map. It polls the host's `GET /api/runs`, `GET /api/host` and `GET /api/inbox` every second and draws the newest run on a pannable, zoomable canvas. It finds the host at `$AEOLIAN_ADDR` (default `127.0.0.1:7431`), the same as the CLI, and never opens the database.

```sh
npm install
npm start
```

The booklet on the left carries the run on the canvas: its goal and state, how long it has run, how many agents have handed off, and power, the live agents not blocked on a spawn against the host's `max_agents` (from `GET /api/host`). Under it the run's agents are listed as tracks in the order they started: hovering one outlines its window, and clicking flies to it, focusing a live agent's terminal; a finished one is only flown to, never resumed from the list. Then the runs, newest first: click one to put it on the canvas, which detaches every terminal of the run that was there; click the newest to go back to following whatever run starts next. The key legend at the bottom is generated from `keymap.ts`.

**Ctrl+Shift+O** swaps the canvas for the inbox, the finished runs the host has not had acked (`GET /api/inbox`), and back. The canvas stays where it was underneath: every terminal stays attached and the camera does not move, but no terminal takes keys while the inbox is up. The pill wears the inbox count as a badge, hidden at zero; clicking it does the same swap.

The inbox lists those runs oldest finished first, each with its goal, state, the step that ended it and when it finished (`HH:MM`, with the date in front when it was not today); an empty inbox says nothing waiting. Click an entry to open it: the ending step's handoff, its worktrees, whose paths copy to the clipboard on click, and on a failed run the tail of that agent's log. Entries open independently and close again when you leave the inbox. **put on canvas** pins the run, as clicking it in the runs list does, and swaps back to the canvas. **ack** asks the host to take the run out of the inbox (`POST /api/runs/{run}/ack`); the entry goes on the next poll, and if the host refuses it stays and the error shows above the list. A run with a source was started by something else (an adapter, a script) and is that source's to ack, so its entry says `waiting on <source>` instead and offers no ack.

**+ new run** in the runs list swaps the canvas or the inbox for the picker, and pressing it again, or **cancel**, goes back to whichever it came from; Esc does nothing here. The canvas stays underneath as it does for the inbox. The picker lists the built-in freeform first, then every workflow in `$AEOLIAN_HOME/workflows` (`GET /api/workflows`, fetched each time it opens) with its steps and description; a file that does not parse is greyed out with its error and cannot be picked. Click one to open its goal box, where Enter starts the run and Shift+Enter breaks the line. Freeform can start with the goal left empty, under the `freeform · HH:MM` label, and its lead then asks what you are working on; a goal typed for it goes to the lead, which starts from it; a folder workflow needs a goal before **start** does anything. Nothing typed in the goal box reaches the canvas or a terminal, the key chords included. A run that starts swaps back to the canvas following the newest run; if the host refuses it, or the folder cannot be listed, the error shows in the picker. **Ctrl+Shift+O** from the picker goes to the inbox.

The run's steps go top to bottom in workflow order. A step that has not started is a dashed placeholder card with its name; a live agent is a window holding its terminal, a finished one is a card of the same fixed size (`cardW` × `cardH` in `dials.ts`), with a helper docked to the right of the agent that spawned it. A step's or role's ink colours its window's top rule and header. Its mark is a kamea sigil seeded from its `mark:`, or from its name when it has none, so the same mark always draws the same sigil; the sigil is traced in stroke by stroke as the window appears. A dotted rule joins each step to the next, and a solid one joins an agent to each of its helpers.

The map compares each poll with the last and moves only what changed. A step that starts grows its window out of its placeholder card; an agent that finishes shrinks to its card, and one that resumes grows back to its session's size; a new helper slides out from behind its parent's right edge. When an agent hands off, a token travels its rule: down to the next step, which turns the rule solid behind it, or back along the dock rule to a helper's parent. The first poll of a run, at start or after switching runs, draws it as it stands, with no motion. The timings are in `dials.ts`; with reduced motion on, everything lands in the same place without travelling. Zoomed far out, a live window becomes a card with its last line of output. A finished agent's card always shows the first line of its handoff, or `killed` when it has none.

Drag the canvas (or hold space and drag, or use the middle button) to pan, and the wheel to zoom. Click a window to fly to it and type into its agent; Esc always goes to the agent. A click on empty canvas or **Ctrl+Shift+F** leaves the terminal and flies back to the whole run. Drag a window's bottom-right corner to change its session's columns and rows; zooming never resizes anything. Click a finished card to open it in place over its neighbours with its full handoff; empty canvas, another window or **Ctrl+Shift+F** closes it. **resume** in an open card's header has the host resume it (`claude --resume` in its old folder) and attaches; nothing else resumes an agent. **kill** in a window's header asks the host to stop that agent.

The only tmux command the map runs is `attach`: each window is its own client, so closing a window or the whole app only detaches. Resizing a window resizes that client, which resizes the session. **New Window** (Ctrl+Shift+N) opens another map.
